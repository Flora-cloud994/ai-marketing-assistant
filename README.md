# AI 跨境电商营销助手

只填一个产品名，自动补齐品类、价格带、人群、卖点、关键词，并沿着「选品 → 建站 → 内容 → 上架 → 投放 → 成交 → 履约 → 复盘」生成 8 大步 32 个工具。

**纯前端单文件，双击即用。** 不需要账号、后端、构建环境。

---

## 为什么做这个

做选品的日常是：开六个页面搜词、抄竞品价、翻评论区、另存表格、凭感觉定价，同一份数据抄五遍，各步结论还互不相通。

这个工具把输入收敛到**一个产品名**，后面的判断都基于同一份数据 —— 改一个数，六章报告一起重算。

## 核心动线

| 步骤 | 做什么 | 关键设计 |
|---|---|---|
| **① 关键词** | 核心词 / 场景词 / 长尾词分组，标注各自用于标题、广告还是内容选题 | 联网时用亚马逊下拉框实时建议词替换模板词 |
| **② 分品类** | 大类（15）› 形态（89 细分画像）› 功能（23 类购买动机）三层识别 | 识别不出就标红「待确认」并屏蔽跨类目结论，不硬猜 |
| **③ 竞品分析** | 同形态 8 个细分款的价位区间、结构差异、核心人群；价差分级判定关系 | 实时在售表列原值（标题/价格/评分/评论数），月销不估算 |
| **④ 评论采集** | 差评共性 + 口碑分布 + 缺口定位 | 正文靠粘贴导入或 CSV，页面如实说明拿不到 |
| **⑤ 值不值得做** | 需求 / 利润 / 风险一票否决，竞争只决定「怎么进」 | 四关放行，把结论变成可复核的结构 |
| **⑥–⑧ 其余七步** | 平台与独立站、内容与视觉、上架与多语言、投放与 KOL、订单风控、物流售后、数据复盘 | 共用同一份卖点数据，改一处全链同步 |

## 快速开始

**直接用成品**：打开 `dist/AI营销助手.html`。

**改源码**：编辑根目录的 `*.js`，然后重新打包——

```bash
node build.js          # 生成 dist/AI营销助手.html（把 16 个脚本内联成单文件）
```

## 联网（可选）

页面是 `file://` 打开的本地文件，浏览器同源策略不允许它直接读 amazon.com 的响应，亚马逊也不给跨域头 —— 这是浏览器硬限制，不是少写了几行代码。

所以「转发」和「解析」是分开的：转发器只做代取网页，解析全在浏览器里。一套代码三档自适应，右上角状态灯显示当前档位：

| 档位 | 要做什么 | 能拿到什么 |
|---|---|---|
| **实时 · 中转** | 部署 `scripts/relay_worker.js` 到 Cloudflare Worker，地址填回面板。一次部署，永久有效 | 品类确认、当天 6 款在售真实价格与评分、10 个实时建议词 |
| **实时 · 公开源** | 什么都不做，借第三方 CORS 代理 | 同上，但代理常被限流 |
| **离线 · 基线** | 全断 | 类目画像，页面明写「不是今天的数」 |

本地调试用零依赖版：

```bash
node scripts/relay_node.js          # 监听 127.0.0.1:8787，页面会自动发现
```

需要评论**正文**时用 Python 桥（带 Playwright，能过登录墙）：

```bash
python scripts/amazon_bridge.py --serve
```

`scripts/relay_worker.js` 由 `node sync-worker.js` 从 `net.js` 自动生成，请勿手改。

## 说清的边界

- **评论正文**：亚马逊现在要登录才给 `/product-reviews/` 页面，公开链路只能拿到数量和评分分布，正文需导入 CSV 或用本机桥。
- **月销量**：平台不公开，不给估算值。
- **海报**：不生成真实图片，只输出符合亚马逊详情页规范的提示词。
- **品类识别**：本地知识库覆盖 15 大类 / 89 细分，超出范围会标「待确认」而不是硬归类。

## 数据与隐私

所有计算在浏览器本地完成，输入内容存在 `localStorage`，不上传任何服务器。仓库内不含任何密钥或账号信息。
