# AI 跨境电商营销助手

只填一个产品名，自动补齐品类、价格带、人群、卖点、关键词，并沿着「选品 → 建站 → 内容 → 上架 → 投放 → 成交 → 履约 → 复盘」生成 8 大步 32 个工具。

**纯前端单文件，双击即用。** 不需要账号、后端、构建环境。

> 在线试用：**https://flora-cloud994.github.io/ai-marketing-assistant/**
> （本地版功能相同；线上版因浏览器限制只能用云中转，见下文「联网」一节）

---

## 为什么做这个

做选品的日常是：开六个页面搜词、抄竞品价、翻评论区、另存表格、凭感觉定价，同一份数据抄五遍，各步结论还互不相通。

这个工具把输入收敛到**一个产品名**，后面的判断都基于同一份数据 —— 改一个数，六章报告一起重算。

## 核心动线

| 步骤 | 做什么 | 关键设计 |
|---|---|---|
| **① 关键词** | 核心词 / 场景词 / 长尾词分组，标注各自用于标题、广告还是内容选题 | 联网时用亚马逊下拉框实时建议词替换模板词 |
| **② 分品类** | 大类（15）› 形态（89 细分画像）› 功能（23 类购买动机）三层识别 | 识别不出就标红「待确认」并屏蔽跨类目结论，不硬猜 |
| **③ 竞品分析** | 同形态 8 个细分款的价位区间、结构差异、核心人群；价差分级判定关系 | 实时在售表列原值（标题/价格/评分/评论数），月销不估算 |
| **④ 评论采集** | 差评共性 + 口碑分布 + 缺口定位 | 正文靠粘贴导入或 CSV，页面如实说明拿不到 |
| **⑤ 值不值得做** | 先算「供需账」，再过四关放行：需求 / 利润 / 风险一票否决，竞争只决定「怎么进」 | 供需比 ≥0.8 才进、<0.3 放弃；估算只排序、实测才判档 |
| **⑤+ 上架体检** | 上架前过一遍 8 维 100 分：标题 / 五点 / 主图 / A+ / 描述 / 定价 / 评论门槛 / SEO 覆盖 | 能算的给实测值，图 / A+ / 描述没数据就标「待核」，不编分 |
| **⑥–⑧ 其余七步** | 平台与独立站、内容与视觉、上架与多语言、投放与 KOL、订单风控、物流售后、数据复盘 | 共用同一份卖点数据，改一处全链同步 |

### 供需账：每个卖家能分到多少流量

选品不是「这个类目大不大」，是**这块饼分给多少人**。

```
供需比 = 月搜索量 ÷ 在售卖家数
```

| 比值 | 判断 |
|---|---|
| ≥ 1.0 | 供不应求，基础曝光不错 |
| 0.8–1.0 | 可进，但要有一个明确差异点 |
| 0.3–0.8 | 偏挤，得靠长尾词和广告撑 |
| < 0.3 | 红海，自然流量分不到，很难出单 |

- **分母**取亚马逊搜索结果总数（页头 `1-16 of over 50,000 results` 那一行），它就是这个细分下的全部在售，比逐款数链接更准也更快。联网即真值。
- **分子**（月搜索量）平台不公开，需自己填：卖家精灵 / Helium10 搜同一个词，抄进侧栏「手动修改 › 月搜索量」。
- **趋势**看最近三个月的月搜索量，连续上涨（哪怕每月 5%）就算需求在长。历史靠本页按月累计，第一次打开时为基准月。

> **重要**：分子是估算时，这一栏只做「组内横向排序」，不套绝对阈值 —— 估值套阈值会给出过度乐观的结论。分子分母都真，才按上表判档。页面上用绿色/灰色区分，`≈` 即估算。

### 上架体检：把「等上架再调」提前到上架前

选品决定「做不做」，Listing 决定「上架那天能不能起量」。这一节把平台实际影响的八个维度摊成 100 分：

| 维度 | 权重 | 这一版怎么算 |
|---|---|---|
| Title 标题 | 15 | 自动拼一版骨架（核心词打头 → 属性词 → 痛点/场景收尾），查字符数、核心词位置、必进词装下了几个、违禁词 |
| Bullets 五点 | 15 | 五条是否齐、每条有没有分到一个词、词有没有重复、开头是不是利益短语（卖点没填够会直接扣分） |
| Images 主图 | 15 | **待核** —— 给 7 张清单，不替你的图打分 |
| A+ 内容 | 10 | **待核** —— 给 5 个模块清单（需品牌备案） |
| Description 描述 | 10 | **待核** —— 给结构清单（问题 → 方案 → 不适合谁 → 清单） |
| Pricing 定价 | 10 | 与类目价格带中位比，低于中位 5–15% 满分，高于 25% 接近零分 |
| Reviews 评论 | 15 | 口径是**门槛**不是你的评分：头部前 3 评论中位 <500 条算好进，>10000 条基本封死首屏 |
| SEO 覆盖 | 10 | 标题 + 五点实际装下多少目标词，扣掉重复堆砌的分 |

维度与权重来自 GitHub 开源 skill **[nexscope-ai/Amazon-Skills](https://github.com/nexscope-ai/Amazon-Skills)** 里的 `amazon-listing-optimization`（其 8 维审计为 Title 15 / Bullets 15 / Images 15 / A+ 10 / Description 10 / Pricing 10 / Reviews 15 / SEO 10）。开源版靠抓页面 + 大模型判断，这里改成纯前端可复算的版本：**能算的算，算不了的留白**——三项共 35 分单列、不进分母，页面上显示「已核 X/65 · 折算 Y/100」。

同时输出一张**埋词覆盖矩阵**：每个词只安排一个主战场（标题拿曝光、五点拿转化、描述收长尾、竞品词只投广告），一眼看出哪些词还悬着。

## 快速开始

**直接用成品**：打开 `dist/AI营销助手.html`。

**改源码**：编辑根目录的 `*.js`，然后重新打包——

```bash
node build.js          # 生成 dist/AI营销助手.html 与 docs/index.html（把 16 个脚本内联成单文件）
```

## 部署到 GitHub Pages

`docs/` 是构建产物目录，`node build.js` 会同时写 `dist/` 和 `docs/index.html`，两边永远一致 —— 不要手改 `docs/`。

开启方式：仓库 `Settings` → `Pages` → Source 选 **Deploy from a branch** → Branch `main`、目录 `/docs` → Save。一两分钟后访问：

```
https://<你的用户名>.github.io/ai-marketing-assistant/
```

> 线上版（https）访问不了 `http://127.0.0.1` 上的本机桥 —— 浏览器会按混合内容拦截。所以网页版只能用「云中转」或「公开源」两档，本机桥只在本地双击打开时用得上。

## 联网（可选）

页面是 `file://` 打开的本地文件，浏览器同源策略不允许它直接读 amazon.com 的响应，亚马逊也不给跨域头 —— 这是浏览器硬限制，不是少写了几行代码。

所以「转发」和「解析」是分开的：转发器只做代取网页，解析全在浏览器里。一套代码三档自适应，右上角状态灯显示当前档位：

| 档位 | 要做什么 | 能拿到什么 |
|---|---|---|
| **实时 · 中转** | 部署 `scripts/relay_worker.js` 到 Cloudflare Worker，地址填回面板。一次部署，永久有效 | 品类确认、当天 6 款在售真实价格与评分、10 个实时建议词 |
| **实时 · 公开源** | 什么都不做，借第三方 CORS 代理 | 同上，但代理常被限流 |
| **离线 · 基线** | 全断 | 类目画像，页面明写「不是今天的数」 |

本地调试用零依赖版：

```bash
node scripts/relay_node.js          # 监听 127.0.0.1:8787，页面会自动发现
```

需要评论**正文**时用 Python 桥（带 Playwright，能过登录墙）：

```bash
python scripts/amazon_bridge.py --serve
```

`scripts/relay_worker.js` 由 `node sync-worker.js` 从 `net.js` 自动生成，请勿手改。

## 说清的边界

- **评论正文**：亚马逊现在要登录才给 `/product-reviews/` 页面，公开链路只能拿到数量和评分分布，正文需导入 CSV 或用本机桥。
- **月销量**：平台不公开，不给估算值。
- **海报**：不生成真实图片，只输出符合亚马逊详情页规范的提示词。
- **品类识别**：本地知识库覆盖 15 大类 / 89 细分，超出范围会标「待确认」而不是硬归类。
- **月搜索量**：亚马逊不公开，本页默认给类目基准估算；要准确判断请手填卖家精灵的数字。卖家数可联网取真值。

## 数据与隐私

所有计算在浏览器本地完成，输入内容存在 `localStorage`，不上传任何服务器。仓库内不含任何密钥或账号信息。
